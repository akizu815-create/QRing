## 既存コードの取得

対象スプレッドシートをPCで開き、「拡張機能 → Apps Script」を選ぶ。編集画面のURLを共有するか、`updateQringReports()`と呼び出し先のコードをテキストとして提供する。URLだけでこちらの読取権限が得られるとは限らない。Webアプリとしてデプロイする必要はなく、デプロイURLを新規作成する必要もない。既存コードや認証情報を公開GitHubへ貼り付けない。

## 接続前に確認する設定

GA4の**数値プロパティID**と閲覧権限、プロパティのタイムゾーン`Asia/Tokyo`、Apps Scriptの既存高度なサービス`AnalyticsData`、既存更新関数の終了位置・エラー処理・Lock・更新状況書込範囲を確認する。`G-M75FF9RHJ6`は測定IDであり数値プロパティIDではない。現行の9〜10時トリガーを新規作成・変更しない。

既存コードの最後に`更新状況`を全置換する処理がある場合、その**後**に追加呼出しが来る必要がある。既存がScriptLockを保持したままの場合、新関数のLockにより`busy`になるため、ロック解放後の安全な呼出し箇所を決める。未確認のまま追記しない。

## データ契約

追加先は`GA4_AI流入元`のみ。列は`日付 / AIサービス / 参照元 / メディア / セッション`ではなく、**4列**の`日付`、`AIサービス`、`参照元 / メディア`、`セッション`。`更新状況`には同名ラベルの専用1行だけを書き、既存6タブを変更しない。

毎回、JSTの前日までの90日を取得する。当日進行中の数値を確定値にしない。`date`、`sessionSourceMedium`、`sessionDefaultChannelGroup`と`sessions`をページング取得。別のAI Assistantチャネル集計と日別照合し、両方の全取得・検証が終わってから書き込む。5万行超、しきい値、サンプリング、欠落、タイムゾーン未確認、照合不一致は更新失敗とする。

ChatGPT・Perplexity・Claude・Gemini・Copilotの候補ホストを完全一致で分類する。実APIで返ったものだけを採用し、これら全サービスの流入を確認済みとはしない。AI Assistantだが候補ドメインで判別できない場合は`不明`。Google/Bing全体、Direct、名前だけのUTM、似たドメインから推測しない。パスやクエリ文字列、メールアドレスはシートへ出力しない。

候補ホストがReferral等に分類されることもあるため、AI別レポート全体と既存AI Assistantの総計が常に一致するとは限らない。コードの照合対象は**元レポート内のAI Assistant部分と対照レポート**。参照元欠落やアプリの参照元制限による未識別流入は復元できない。Google AI概要・AIモードを一括してAI Assistantへ加えない。

- その日に他のトラフィックが観測され、AI該当行がない: `該当なし / — / 0`（取得範囲内の観測0件）。
- その日のトラフィック自体がない: `未確認 / — / 空欄`（計測稼働を証明できない）。
- 90日すべて空: `NO_TRAFFIC_DATA`で旧データを保持し、更新状況は未確認。
- API失敗: 旧成功データを消さず、追加集計の失敗を専用状態行へ記録。状態行の書込も失敗した場合は`statusRecorded:false`を返す。
- 同じ期間を再取得: 90日分を置換して重複を避け、期間外の履歴を保持。既存タブのヘッダーや行形式が想定外なら上書きしない。
- シート書込中の障害はトランザクション保証できない。`WRITE_STATE_UNCONFIRMED`として範囲を人が点検し、旧データが必ず無傷と断定しない。

プロパティのデータ保持・権限・しきい値等により90日取得できるかは実接続で確認が必要。APIの遅延確定分は次回90日再取得で更新される。ランディングページ別集計は今回は追加しない。
