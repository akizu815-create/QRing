## 追加費用0円で始める案（推奨）

既存のChatGPT契約と8時タスクをそのまま使う。作成結果を管理者が確認し、運用者が構造化・出典確認・CLI取込し、編集/確認/承認、公開用スナップショット検証、PR、最終公開承認の順に進める。ChatGPTタスクの出力を非公開DBへ自動転送する接続は現在存在しない。契約内の利用制限、原稿の受け取り確認、手作業の時間は残る。

ローカルでの取込・編集・承認は新規AI料金を必要としない。ただしiPhoneで操作するには、既存認証を利用した非公開管理サーバーの設置・永続DB・バックアップが残る。既存設備や無料枠で収まるか確認してから構築する。GitHub Pagesの静的ホスティングだけではこの管理サーバーは動かない。

運用者向け取込例（非公開の作業ディレクトリとDBを使用）：

```sh
python3 -m scripts.editorial.cli import --actor OPERATOR --db /private/path/editorial.sqlite3 < /private/path/article-packet.json
```

`article-packet.json` は `{"article": {...}, "evidence": [...]}`。詳細な既存型と取込条件は `src/lib/columns/types.ts`、`scripts/editorial/cli.py`、`scripts/editorial/core.py` を参照。JSON整形だけで承認済みにはならない。操作名actorはCLIの本人認証ではないためOSアクセスを管理する。未公開原稿・根拠抜粋・DBを公開GitHubや公開Actionsログ/成果物に置かない。

## 二重生成と公開の分離

- 現在の生成主体は既存ChatGPTタスクのまま。新cron、AI有効化、タスク変更は実施しない。
- CLI取込と新生成器は同じJST日付の一意制約を使う。取込済みの日は新規生成せずその下書きを編集する。ただしChatGPT側の原稿作成自体をDBから止める接続はないため、将来の切替時は既存タスクの停止確認と明示承認が必要。
- 下書き→確認・修正→確認記録→記事承認→公開準備→検証→PR→本番承認。記事承認ではデプロイされない。
- main pushでの既存Pagesデプロイは維持。今回のPRをマージするとデプロイが始まるため、最終承認まではマージしない。
