# コラム導線・内部リンクの追加

対象：`feat/column-navigation`。既存の統合実装計画・承認ルールを維持。本番マージ・公開は行わない。

## 変更

- ヘッダーのPRICEとNEWSの間にCOLUMN／コラムを追加。PC・モバイルが共用するNAV定義を使用。自治体・問い合わせ・マイページを維持。
- HOMEのFOR BUSINESSの後にCOLUMNセクションを追加。公開済み・公開日時到来済みの共通抽出結果から最新3本までを静的表示。現在2本なので2本だけ。営業バナー・空カードは作らない。既存の支援告知は維持。
- 自治体ページの既存コラム導線を維持し、主読者municipalの公開記事があれば3本まで表示。記事には、CTA設定に依存しない自治体サービスへの本文内リンクを用意。
- 活用シーンと記事データの`relatedService.href`を照合し、関連する公開記事を3本まで表示。既存の高齢者・落とし物記事を引き継ぐ。ペットは対象記事がないので空セクションや無関係な記事を表示しない。
- フッターをCOLUMN見出しとコラムリンクへ整理し、自治体向け記事一覧への導線を併設。既存の他リンク・開閉操作は維持。
- 記事が増えた場合の一覧を静的ページ送りに変更。未絞り込み時の前後ページは通常のHTMLアンカー。カテゴリー・読者絞り込み中のページ送りのみ既存のクライアント操作を使用。
- 執筆者が明示した関連記事を優先し、逆方向の指定も考慮して3本まで表示。関連性を指定していない記事を自動で大量追加しない。相互リンクの不整合は監査で検出する。
- 公開記事の通常一覧・自治体一覧からの到達性、最新順、内部リンク切れ、孤立記事、関連記事・サービスへの帰路を監査する。

既存の記事URL・本文・出典・公開日・サービス仕様・正式問い合わせ先は変更しない。AI・GSC認証や課金・承認運用は変更しない。

## ページ送り

`/column/`、`/column/page/2/`…、自治体は`/column/audience/municipal/`、`/column/audience/municipal/page/2/`…となる。2ページ目以降は自己canonicalと固有タイトルを持ちサイトマップへ追加。すべての公開記事を通常の一覧リンクでたどれる。

静的出力で記事数0～9本の場合も動的ページ定義を保持するため、`page/1/`も生成するが、これはcanonicalを元一覧とするnoindexの別名。ナビゲーション・サイトマップでは使用しない。記事の重複URLを作る変更ではない。
