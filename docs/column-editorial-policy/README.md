# 公式コラム：名称・出典・時事情報の恒久編集方針

適用開始：2026年11月28日。代表者からの「公式コラム制作における企業名・商品名・サービス名の掲載方針」を編集上の基準とする。今後の企画・制作・改訂・公開前審査と、既存記事の点検に適用する。本書の策定は、既存記事の自動改稿や例外掲載の承認を意味しない。

## 主題と名称

原則として、特定の民間企業・商品・サービスを名指しで紹介・評価・宣伝・批判する記事を制作しない。主題は社会課題、生活上の疑問、科学、技術、制度、文化、心理、プライバシー等とする。

掲載可能なのは、国・行政機関・自治体、公的機関・大学・研究機関、法令・行政制度・公共サービス、公共性の高い社会インフラ、PHP・QRコード等の技術／規格名称、株式会社QRing・つながるQR。

NHK・日本郵便・郵便局・NTT・JR・Suica等は、公共性の高い事業やサービスの説明に**必要な範囲だけ**掲載できる。社名全体や関連するあらゆる商用サービスを許可したものではない。技術名称としてのPHPと、同名・類似名の企業・出版物を区別する。

他の民間企業、他社商品・サービス、競合、特定のホテル・宿泊施設、スマートタグ・GPS機器、AI・通信・ITサービスの名称は原則掲載しない。知名度や普及率だけで公共インフラと扱わない。協業先・実証実験先も、代表者の個別承認がなければ掲載しない。

個別判断は独断で掲載しない。記事のid／slug、対象版、掲載箇所、名称／URL、必要性、代替案、代表者の判断と根拠となる参照先をレビュー記録に残す。前の記事の許可を別記事・別版・別目的へ自動流用しない。承認が確認できなければ公開を保留する。

学会・公益法人・非営利団体を、公的機関と自動的に同一視しない。原著論文の出版社名、商標帰属表示、研究史に不可欠な開発企業の記載も、必要性と方針との関係が明確でなければ個別判断へ回す。法的な帰属表示を無断で消して適合させない。

## 時事ニュース・因果関係

漏えい・攻撃・障害等は社会的背景や技術の仕組みを説明する。個別企業の被害を批判したり、つながるQRの優位性を訴える材料として利用しない。

以下を別の事実として扱う。

| 区分 | 混同してはいけないこと |
|---|---|
| 脆弱性の存在 | 弱点があることと、悪用・侵入・漏えいが起きたことは別 |
| 脆弱性の実悪用 | 悪用の確認と、特定の侵入・漏えいとの因果関係は別 |
| 不正アクセスの発生 | 侵入したことだけで個人情報の取得・流出まで確定しない |
| 漏えいの確認 | 公式に確認された対象・範囲・時点を限定して書く |
| 漏えいの可能性 | 確定事実へ言い換えない |
| 調査中 | 原因・被害・影響範囲を断定しない |
| 予防的なサービス停止 | 被害発生による停止とは限らない |
| 被害によるサービス停止 | 公表された原因と確認範囲を超えない |
| 通常のシステム障害 | 攻撃や漏えいを原因として推測しない |

公式資料で確認できない因果関係は記載しない。発表の日時・更新版・確認済み／可能性／調査中を内部の根拠記録に分ける。別々の発表を時間が近いだけで結び付けない。企業名を伏せても、出来事や固有条件から特定企業への攻撃・漏えいを推測させる記事にしない。

## 公開する出典と内部の事実確認

公的機関、行政、大学、研究機関、公式技術文書、原著論文を優先する。名称だけで発信主体を判断せず、URLの所有者・資料の発行者・版・対象範囲を確認する。

民間企業の公式発表は**内部の事実確認**に利用できる。ただし、その社名・商品名・サービス名・URLを公開記事へ自動転載しない。「一次資料」「公式技術文書」であることだけでは、名称や企業ドメインの公開許可にならない。内部用の抜粋やURLは非公開の調査資料に残し、公開するArticle.sourcesとは区別する。

公開可能な出典では根拠を示せない主張は、意味を歪めない範囲で修正するか掲載を見送る。特定サービスだけで確認した仕様を、社名を消して「どのサービスにも共通」と一般化しない。発明者・開発主体等の事実を不正確にしてまで匿名化しない。適切な代替資料が見つかるまでは、裏付けのない出典差し替えや削除をしない。

## 公開前の必須チェックリスト

- [ ] 主題が個別企業・商品・サービスの紹介・評価・宣伝・批判になっていない。
- [ ] タイトル、見出し、SEO title、description、概要、本文を確認した。
- [ ] 参考資料の表示名、外部URLとリンク先の所有者を確認した。短縮URL・リダイレクトも確認した。
- [ ] 内部リンクの文言、関連記事カードのタイトル、リンク先で案内する内容を確認した。
- [ ] 画像原本を目視し、画像内の文字・ロゴ・透かし・特定製品の描画を確認した。判読できなければ未確認とした。
- [ ] alt、OGP画像・title・description、JSON-LDのheadline・description・image・citation・publisher等を確認した。
- [ ] 共通ヘッダー／フッターと共通のロゴ・OGP等、記事データ外の出力も確認した。
- [ ] 公共インフラ例外は説明上の必要性を確認し、他の商用サービスへ拡張していない。
- [ ] 時事情報の9区分と、資料が確認した因果関係・未確認部分を区別した。
- [ ] 公開可能な根拠がない主張を、意味を変える一般化で残していない。
- [ ] 協業先・実証先・その他の例外には、この記事・この版について代表者が個別承認した根拠がある。
- [ ] 判断保留・修正候補を代表者へ報告し、未確認を適合確認済みとして扱っていない。

## 制作・審査への組み込み

- 企画では既知の他社名を中心とした検索語を制作候補から保留し、元のSEO観測値は残す。入力テーマもAPI呼出し前に確認し、不適合なら一般的な課題を主題として企画し直す。企業固有の条件を単に匿名化しない。
- AI下書き用のsystem指示にも本方針を含める。有料生成の有効化・契約・モデル設定は変更しない。
- 非公開編集画面では、従来の出典・主張・仕様確認と別に、本方針の全対象を確認した明示チェックを必須にする。検出候補があれば公共性や出典区分の判断記録も必須。禁止候補を残す場合や出典の掲載区分が未確定の場合は、実際の代表者個別判断の参照先を記録する。
- 記録は対象版・確認actor・指摘とともに非公開編集履歴へ保存する。参照先の入力は本人認証された代表者承認そのものではない。人が実際の承認を確認する。生成器や原稿入力から確認済み状態を注入できない。
- 編集保存後は従来どおり版が進み、確認・承認が失効する。旧版・旧方針の確認を使って新しい公開準備をしない。
- 月次packetを直接登録する運用でも、以下の報告と**全チェックリスト**を月次PRへ添付し、代表者が内容・版・日時と一緒に確認する。機械検査の0件を人の確認の代用にしない。

```sh
python3 -m scripts.editorial.audit_policy --file /path/to/private-month-packet.json --output /tmp/policy-report.json
```

指定なしではmainの登録30記事を点検する。既存記事の点検コマンドは公開処理ではなく、検出候補を報告する。入力・出力に私的原稿がある場合は公開リポジトリ外へ保存する。

この変更は制作・審査のルールであり、自動公開の日時・課金・配信・監視ロジックを変更しない。既存30記事の本文・SEO・画像・版・予約設定も変更しない。既存の抵触候補は [監査結果](existing-article-audit.md) で報告し、本文等の変更は別途レビューする。

実装と検証範囲は [implementation-and-validation.md](implementation-and-validation.md) を参照。

## 自動検査の限界

名称・ドメイン辞書と法人表記による検出は補助。未登録の企業、別名、同音語、ロゴ、URL所有者の変更、必要性や因果関係の意味は完全に判定できない。公的に見えるドメインの一致も内容の正確性や掲載許可を保証しない。未知の出典は要確認とし、画像や最終出力は人が確認する。検出候補を全件「違反確定」、未検出を「完全適合」とは扱わない。
