### 作成するフォーム（そのまま使える文面案）

フォーム名：**つながるQR｜販売開始のお知らせ**

冒頭：

> つながるQRの一般向けサービス開始について、メールでのお知らせをご希望の方は、以下よりご登録ください。

利用目的・取扱い：

> ご入力いただいたメールアドレスは、株式会社QRingが、つながるQRの一般向けサービスの販売・提供開始のお知らせ、および配信停止・削除のご依頼への対応に使用します。ご登録は任意です。送信により、この目的でメールでのお知らせを希望するものとして受け付けます。ほかの商品や継続的な営業案内には使用しません。氏名・電話番号・住所の入力は不要です。
>
> 回答はGoogleフォームと専用のGoogleスプレッドシートで管理し、担当者に限って取り扱います。個人情報の取扱いは、株式会社QRingのプライバシーポリシーをご確認ください。
> https://www.qring.jp/privacy/
>
> お知らせが不要になった場合や登録情報の削除をご希望の場合は、ご登録のメールアドレスから info@qring.jp へ「販売開始通知の停止希望」または「販売開始通知の登録削除希望」とご連絡ください。停止のご依頼があったアドレスは配信対象から除外します。
>
> ご登録は商品の予約・購入申込みではありません。販売・提供開始の時期は未定です。

入力項目は1つだけ：

| 設定 | 値 |
| --- | --- |
| 質問 | メールアドレス |
| 形式 | 記述式（短文） |
| 必須 | オン |
| 回答の検証 | テキスト → メールアドレス |
| 説明 | お知らせを受け取るご本人のメールアドレスをご入力ください。 |

明示した目的への通知希望を送信で受け付ける方式。氏名・電話番号・住所・ペット情報を追加しない。メール形式の検証は、本人性・実在・到達可能性を確認するものではない。

送信後の確認文：

> ご登録を受け付けました。販売・提供開始のお知らせは、ご入力のメールアドレス宛てにお送りします。停止・削除のご依頼は info@qring.jp へご連絡ください。これは予約・購入申込みではありません。

上記は運用案であり、受付前に、info@qring.jpで停止・削除対応を担当できること、保存期間・Google利用の説明と社内管理が整っていることを確認する。プライバシーポリシー本文は変更しない。受付開始前に必要な説明の確定を待つ。

### ユーザー側の設定手順

1. 会社で管理するGoogleアカウントでGoogleフォームを新規作成。ペットアンケートのコピーや既存回答の流用はしない。上のフォーム名・説明・質問を設定する。
2. 設定のメールアドレス自動収集は「収集しない」。独立した上記の記述式質問で入力してもらう。「確認済みメール」を収集する設定は使わない。メール収集の「回答者からの入力」方式を選ぶ場合も二重の入力欄を作らず、必須・メール形式・ログイン不要を実機で確認する。本案は独立した1質問方式を優先する。
3. 「回答を1回に制限」はオフ。組織・ドメイン・特定Googleアカウントへの回答者制限を付けない。ログイン必須になるファイルアップロードや確認済みメール収集は使用しない。
4. 回答編集・クイズ・回答コピーの自動送信は本案では不要。特に「結果の概要を表示」はオフにして、他人のメールアドレスが回答者へ見えないようにする。
5. 回答タブから保存先に**新しい専用スプレッドシート**を作成し、例として「つながるQR｜販売開始通知・回答管理」と命名。フォームとシートの編集権限は必要な担当者だけ。シートの「リンクを知っている全員」公開・ウェブ公開はしない。フォームの回答者公開と編集者・シート共有を混同しない。
6. 送信後の確認文とプライバシーポリシーリンクを確認。「公開」で回答者の一般アクセスを「リンクを知っている全員」にする。回答受付をオンにし、回答者リンクをコピーする。編集用URLはサイトへ載せない。
7. 下記の送信テストを完了後、実際の回答用URL（/viewform、またはGoogleからコピーした短縮URL）と、テスト結果を共有する。URLやテスト用アドレスをGitHub公開資料へ不用意に記載しない。回答用URLだけがサイト側の設定対象。

Google Workspaceの管理ポリシーで社外回答が制限される場合は、その設定を解消できる担当者へ確認する。設定名が画面で変わる場合も、ログアウトで回答可能という動作を基準に検証する。

## 送信テスト・切替条件

- [ ] フォーム説明が目的・任意登録・プライバシー・停止/削除・予約ではないことを明示している。
- [ ] Googleにログインしていないシークレットウィンドウで、PCと390px程度のスマートフォンからフォームを開ける。
- [ ] メール以外の個人情報・Googleログイン・ファイル添付を要求されない。
- [ ] 空欄や不正な形式を送信できず、担当者が保有するテストアドレスで送信完了できる。
- [ ] 専用回答シートへ時刻とテストアドレスが保存される。シートの一般公開なし。テストアドレスは配信対象から除外する。
- [ ] 他の回答内容・メールアドレスの一覧がフォーム回答者へ表示されない。
- [ ] 同一アドレスの再送信ができても、運用で重複配信しないよう整理できる。
- [ ] 停止・削除依頼を処理する担当と方法が確定し、テスト登録を除外・削除できる。フォーム内回答とシートは別保存なので、削除時は両方を対象にする。
- [ ] 最終フォーム文面・回答用URL・上記の結果についてユーザーが確認し、サイト側導線変更へ進める。

まだいずれも実フォームで確認していない。担当者の管理下にないメールアドレスや架空のアドレスで、第三者宛てにメールが届き得る試験をしない。フォーム送信完了は販売開始通知メールの配信テストではない。

## 回答管理と通知配信（自動システムの完成ではない）

専用シートは受付一覧であり、メールの送信エンジンではない。Apps Scriptやアドオン、新しい外部配信サービスは今回導入しない。

| 項目 | 運用案と未確認事項 |
| --- | --- |
| 保存先 | フォーム原本＋専用回答シート。回答タブを編集せず、別タブの配信管理へアドレス、登録日時、目的/文面版、配信可否、停止日時、配信日時、返送状態を最小限記録する。氏名等は追加しない。個人データはGitHub・GA4へ送らない。 |
| 送信元 | `info@qring.jp`は現行サイトの正式な問い合わせ先として確認済み。ただし販売通知の送信用アカウント権限・差出人名・返信受信・SPF/DKIM/DMARC・送信上限は未確認。候補として責任者が承認してから使い、送信元を確定済みと扱わない。 |
| 送信方法 | 開始時に最新の有効登録一覧を担当者が確認し、会社メールから宛先ごとの個別送信を基本案とする。登録者同士のアドレスをTo/CCへ並べない。配信前にテスト先へ送信し、差出人・返信・停止方法を確認する。人数が多い場合は既存の利用可能な送信手段・制限を確認し、対応不能なら別途配信方法の承認を得る。 |
| 重複 | 前後の空白やドメイン部分の表記を整理し、同じアドレスへ同じお知らせを重複配信しない。ローカル部を勝手に小文字化したり、+タグ・ドットを取り除いて別アドレスを統合しない。曖昧な重複は担当者確認。 |
| 本人性・不正登録 | ログイン不要フォームの入力だけでは本人性は確認できない。自己申告の通知希望であり第三者登録を完全に防げない。本人確認メール（ダブルオプトイン）は未実装。必要になった場合は別設計・承認とする。件数急増は担当者へ通知して確認し、停止リストを勝手に解除しない。 |
| 配信停止 | 登録アドレスからの停止連絡を担当者が確認し、配信前の除外リストへ反映。新しいフォーム回答だけで停止を解除しない。毎回のメールにも停止方法を記載する。既存問い合わせ受付と通知登録の一覧を混ぜない。 |
| 削除・保存期間 | 目的終了後の削除時期・停止管理に残す最小記録を事前に確定。例として「開始通知・返送対応終了後90日以内」は案であり未決定。法務/運用が確認し、必要な保存期間説明をフォームへ反映してから受付する。フォーム回答とリンク先シートはそれぞれ削除確認する。 |
| 誤送信対策 | 最小権限・二者確認、配信直前の停止照合、テスト行の除外、送信済み記録、宛先ごとの送信を行う。メール本文やCSVを公開しない。 |

登録だけで自動配信・到達・全員への確実な通知が保証されるとは説明しない。メール形式が正しくても誤記・迷惑メール振分け・返送・第三者入力の可能性がある。
