## 3. サイズ・比率

公開21枚の実測：1280×720が14枚（16:9、66.7%）、1280×853が2枚、640×384が2枚、1280×421が2枚、800×324が1枚。新作の推奨納品寸法は **1280×720・16:9**。ChatGPT側でこのキャンバスを指定し、制作後に別比率から自動トリミングしない。高解像度の制作元がある場合もユーザー確認用に保持し、縮小等の実装処理は別指示で扱う。

既存06の1280×853や横長01・02は保持する。異なる比率を理由に一律C判定にしない。画像内の余白と、contain表示によって枠内に生じる余白は別物として見る。

形式は制作元PNG等を保存し、WebP等へのWeb納品処理は承認後の別工程とする。今回、変換・圧縮・色補正はしない。容量だけを目的に紙感・顔・毛並みを損なわない。厳格なKB上限を画質確認なしに設定しない。

## 4. 描画・色彩

上品で自然な水彩風。06程度の描き込みを中心に、柔らかい輪郭と自然な陰影を残す。写真、3Dレンダー、強いアニメ表現、均一なベタ塗り、過度な輪郭強調に寄せない。髪や毛を一本ずつ精密化しすぎない。

アイボリー、柔らかいベージュ、自然なブラウン、落ち着いたグリーン、控えめなグレー、自然な肌色を土台とする。淡紫、淡い青、制服の紺など記事に必要な色は許容する。サイトの色は背景・文字の調和確認用で、イラスト全体をその3色に限定しない。

- サイトのアイボリー：`#F7F4EE`
- 深ブラウン：`#1F1A14`
- モスグリーン：`#5B6E4F`

「淡くする」を目標にしない。白飛びした顔や背景、セピア一色、過度な黄み、強い原色、黒い輪郭を避け、基準にある中間色と適度な暗部を残す。20のグレーは設計室の文脈上自然であり、それだけで色調不良とはしない。

## 5. 人物・動物・構図

主役と行動を一つに絞り、原則1つの自然な生活場面で表現する。人物は1～3人程度を目安に、必要以上に増やさない。カメラ目線の記念写真より、相談、確認、散歩、触れ合いなど記事に沿う行動を選ぶ。

## 8. 採用時の確認

1. 記事の要点・サービスの公式仕様に合っているか。誤った機能・効果・法制度を絵で示していないか。
2. 06と補助基準を並べ、水彩・色・陰影・奥行きが合うか。薄さだけで合否を決めていないか。
3. 原画像のピクセル寸法・比率が納品条件を満たすか。後加工でつじつまを合わせていないか。
4. 主役の大きさ・余白・見切れ・手指・動物・遠近・小物が自然か。
5. 無用な文字・住所・電話番号・ロゴ・機能するQR・図解を含まないか。
6. 比較HTMLで旧画像と新候補を同じ枠、containで確認し、PCとスマートフォン双方で読めるか。
7. ユーザーが完成ファイルを明示承認したか。候補のアップロードやC判定を承認として扱っていないか。
8. 承認ファイル名・SHA256・対象記事・承認根拠を記録し、別途差し替え指示を受けてからCodexが実装する。

## 9. 表示仕様とCSS案の境界

現在のコラム一覧は `ArticleList.tsx` の `w-full h-auto`、記事詳細は `ColumnArticle.tsx` の `w-full h-auto`。幅に応じて元比率の高さを使うため、一覧の画像高が揃わない。画像内容の構図差とは別問題であり、現在の構成自体がトリミングしているわけではない。object-fit/object-positionのブラウザー既定値は通常fill/50% 50%だが、h-autoのため縦横比は保たれる。

承認後の一覧限定案（未実装）：16:9の同寸枠内で、元画像全体をcontain表示する。詳細ページは原画像比率のh-autoを維持する。01・02の上下余白、06の左右余白が生じるため、全画面を埋める案ではない。背景は既存アイボリーを候補とし、ユーザー確認後に決める。object-cover、固定幅と固定高による引き伸ばし、画像ごとのcrop/object-position補正は行わない。
