## 優先順位と根拠

1. **08**：文字・制度の区分・複数サービス挿絵が全面に密集。06の生活場面から最も離れた説明パネル。
2. **04**：施設6種を並べたコラージュ。個別施設名や比較は本文で扱い、一場面を制作候補とする。
3. **03**：チェック文・記憶を示す複数の小物・疑問符と人物が同時に視線を引く。
4. **05**：昔/今の左右比較と電話番号一覧・矢印・通信アイコンが説明図を形成。
5. **09・16**：人物の水彩は良好だが、想像枠・ラベル・大きな説明用小物を減らした単一場面の候補を検討。
6. **12**：今回追加した中優先の候補。大きな写真画面・位置ピン・住所標識の説明性が強い。

20は灰色の設計室・細かな描写だけを根拠に差し替えない。現状A・低/要確認として維持。02は人物のない自然な机上の場面として適切で、Bは横長比率による一覧の表示高さだけの検討。

## 表示調査

原画像は1280×720が14/21枚で多数派。推奨新作は16:9・1280×720。現在の一覧・詳細は幅100%、高さautoで自然比率。PCは一覧2列、スマートフォンは1列。元画像比率の違いで画像高が異なるが、画像を切り取っているわけではない。06は約3:2の指定基準として保持する。

一覧・詳細・HOMEのコード確認とPC1280px/スマートフォン390pxの実測は [検証記録](validation.json) を参照。CSSは制作ガイド末尾に提案としてのみ記載。画像の寄り具合・元画像内の余白・画面上の枠余白を別々に評価する。

## レビュー方法

リポジトリをローカルで配信する場合は、リポジトリ直下で `python3 -m http.server 8782` を実行し `/docs/column-image-audit/review.html` を開く。HTMLの画像参照は既存public配下の正本へ相対リンクしており、画像の複製・公開ページの追加は行わない。ダウンロード用の単一HTMLは同じ正本のバイト列を内包し、オフライン閲覧できる。

基準5枚を見てからC判定の候補を確認する。後日、新たに制作されたファイルを各カードでローカル読込すると旧画像と同寸枠で比較できる。自動生成・アップロード・サーバー保存はせず、候補の読込は採用承認を意味しない。元画像は入れ替わらない。

## 変更と検証の境界

変更は `docs/column-image-audit/` の参照資料のみ。既存画像、本文、SEO、URL、公開日時、紐付け、並び順、CSS、予約公開、計測設定は変更しない。Draft PRのみを作成し、mainへマージしない。画像制作・差し替えはユーザー承認済みファイルについて別指示があるまで行わない。
