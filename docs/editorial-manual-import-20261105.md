# ChatGPT原稿の管理画面取込

2026年11月5日。main `bcef904` から `feat/editorial-manual-import` を作成。スマホHEROのPR #115は未マージのまま保持し、本変更は独立したPRにする。

## 今回完成した範囲

既存管理画面に「ChatGPT原稿を下書きに取り込む」を追加した。従来のCLI専用取込を、編集者権限で通常の入力欄から使えるようにする。本文、タイトル、slug、導入文、SEO情報、検索意図、読者・カテゴリー、仕様版、出典・抜粋・主張を入力する。読者とカテゴリーは既存TypeScript定義を利用し、独立して選択する。

本文は `## 見出し` と空行区切りの段落を既存Article構造へ変換する。HTML、Markdownのリンク・表・箇条書き等は実行・展開せず文字として保持する。表や内部リンクの構造化は保存後に既存の詳細編集で行う。空の節・不正slug・未来の出典確認日等は保存しない。

出典は複数登録可能（最大20件）。資料名・HTTPS URL・確認日・20文字以上の抜粋・資料区分と、それが裏付ける主張を登録する。これらを入力しても「確認済み」にはならない。出典の自動取得・検証や未確認情報の補完は行わない。公開予定日は取込日を仮設定し、後から編集可能。公開は自動では行わない。

## 接続と権限

新しい `POST /api/import` は既存の署名付き認証・同一Origin JSON検査・1MB上限をそのまま使い、editor権限だけに許可する。`manual.packet` が許可した入力項目だけをArticleへ変換し、既存CLIと同じ `import_external` へ渡す。

必ず非公開DBの下書き・リビジョン1・承認なし・主張未確認で作成する。公開状態、承認リビジョン等のシステム項目の持ち込みを拒否する。本文や抜粋は `textContent` で表示する。公開JSON、Git、デプロイを変更しない。

JST日付の一意制約をCLI取込・API取込・新生成器で共有する。同じ日の重複取込は409、保存失敗時は入力を維持し、明示的な再操作で合計2試行まで。既存の下書きを上書きしない。元のChatGPTタスク自体はDBから停止されないため、別生成器を有効化する際は以前の方針どおり生成主体の切替承認が必要。

保存後は既存の一覧・全文編集・確認依頼・出典等の確認記録・記事承認・差し戻し・履歴へ接続する。記事を修正すると承認は失効する。記事承認とpublisherの公開準備、本番反映承認はそれぞれ別。

## 利用手順（管理サーバー設置後）

1. 既存8時タスクの原稿を受け取り、本文・出典・サービス仕様を確認する。
2. 認証済み管理画面を開き、「ChatGPT原稿を下書きに取り込む」に必要事項を入力する。
3. 「下書きとして取り込む」を実行し、保存された全文・出典・検査結果を確認する。
4. 修正、確認依頼、確認記録、記事承認の順で進める。
5. 公開用データの準備・検証・PRを行い、管理者の別途本番承認後に反映する。

未保存の入力はブラウザを閉じると失われる。機密原稿をブラウザの永続ストレージに自動保存する機能は追加していない。元原稿を手元にも残す。

## 検証と限界

- 編集系20テスト合格。新規5テストは実HTTPで匿名/権限/Origin拒否、システム項目持込拒否、公開データ不変、API使用量0、同日二重登録、失敗後の明示的再試行、取込→確認依頼→出典確認→承認→修正による承認失効を確認。
- 既存SEO分析18テスト、コラム公開判定、静的出力、導線、SEO foundationとSEO auditに合格。公開18ページの内部リンク切れ・errorsは0。
- `npm run build` 成功、静的29ルート。公開用ソース・写真・記事・認証設定・定期実行/デプロイ設定の差分なし。
- 合成データだけの静的プレビューでスマホ入力欄の16px表示、横はみ出しなし、出典追加・削除、必須項目の検査、入力保持を確認。これは非公開DBにつないだブラウザ保存テストではない。保存・権限・承認の接続はローカルHTTP結合テストで検証。実機iPhone/Safari未検証。

**iPhoneで実運用できる管理URLの設置、既存ログイン基盤との接続、非公開DBの永続保存・バックアップは引き続き未完了。** 認証仕様や既存無料ホストの利用可否はGitHub内から確認できない。開発モードを外部公開して代用しない。公開GitHub Pagesだけでは非公開管理APIは動かない。

新しい有料API、AI呼出し、AI有効化、8時タスク変更、新規schedule、mainマージ、本番デプロイは実行しない。前回の無料運用報告の「取込はCLIのみ」という制限は、本PRのコードでは解消するが、サーバー設置前に実運用できるようになった意味ではない。
