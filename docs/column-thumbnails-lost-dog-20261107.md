## 記事日・公開履歴・承認の扱い

利用者は記事日を2026年11月7日と指定し、公開は11月7日以降の承認後と回答している。

- `editionDate=2026-11-07` は編集上の記事日。
- `publishedAt=2026-11-07` は承認前の予定値であり、現時点の実公開履歴ではない。
- `status=approved`、`publicationPending=true` として、本番用ビルドでは詳細・一覧・サイトマップへ出力しない。予定日を過ぎても、このフラグを解除するまで公開しない。
- Cloudflareのブランチプレビュー（`CF_PAGES=1`、空でない `CF_PAGES_BRANCH` が `main` 以外）のみ、承認リビジョンと品質検査を満たす公開待ち原稿を表示する。通常の下書きは表示しない。
- プレビューは「公開前プレビュー」と表示し、`datePublished`、OGPの公開日時は未設定。記事URLはnoindexとし、実公開までサイトマップへ含めない。
- `reviewedAt=null`、公開時刻は未記録。原稿の `approvalRecord` にはSHA-256と受領日 `receivedOn=2026-11-06` のみ保存する。代表者の監修日・実際の承認日時を推測して追加しない。

## 公開承認後の手順

1. 利用者の公開承認を受けてから、11月7日以降の実際の公開日を確認する。
2. 新記事のみ `status=published`、`publicationPending=false`、`publishedAt=実公開日` へ更新する。`editionDate` と原稿は変更しない。
3. 公開前の予定時刻を実公開時刻として記録しない。実時刻が不明な段階では `publishedTimestamp` を省略し、datePublishedには正しい日付のみを使用する。
4. ビルド・公開対象選択・一覧・本文・SEO・サイトマップを再確認してからmainへマージする。公開対象となった時点で、既存の仕組みが詳細、一覧、ArticleのdatePublished、OGP公開日、サイトマップへ反映する。
5. 本番デプロイの成功と実際のページを確認する。デプロイ成功日時は配信履歴として扱い、監修・承認記録と混同しない。

初回PR作成時は公開承認待ちとしていた。利用者からマージ指示を受領したため、新記事を `status=published`、`publicationPending=false`、`publishedAt=2026-11-07`（日本時間の実公開日）に確定して公開する。公開前プレビュー限定の説明は、承認待ち段階の履歴として残す。正確な公開時刻は未確定のため `publishedTimestamp` は設定しない。監修日時は追加しない。
